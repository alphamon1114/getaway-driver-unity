# 개발 로그

## 2026-09-11 — 도시 격자, 일반 차량, 순찰차 시인성

문제: 맵이 직선 한 줄이라 도시로 읽히지 않았고, 28m마다 찍힌 건물 48~76개가 단조로운 벽처럼 보였습니다. 그리고 순찰차가 "보이지 않는다"는 보고가 있었는데, 모델이 없는 게 아니라 **항상 플레이어 28m 뒤에 스폰되고 추격 카메라는 앞을 보기 때문에 구조적으로 화면에 들어올 수 없었습니다.** 추격 게임인데 추격자를 확인할 방법이 없었습니다.

변경:

- **사거리.** 본선을 가로지르는 교차로를 일정 간격으로 배치하고 경계벽을 그만큼 열었습니다. 측면 도로는 좌우 70m까지 뻗다가 막다른 벽으로 끝나 플레이어가 이탈하지 못합니다. 교차로마다 횡단보도 줄무늬(본선 양쪽 + 측면 도로 양쪽), 네 모서리의 신호등 기둥, 인도를 세웠습니다.
- **건물 축소와 블록화.** 28m 간격 배치를 교차로 사이 블록 단위로 바꿔 블록마다 깊이 30~45m 건물 두 채씩 놓고 사이에 골목을 남겼습니다. 창문 스트립 간격도 4m에서 6m로 늘렸습니다. 건물 수가 48/62/76개에서 20/22/26개로 줄었습니다.
- **일반 차량.** 갓길 주차 차량을 장애물로 배치하고(밀도는 스테이지 필드), 사거리마다 `TrafficCar`가 좌우로 지나다니게 했습니다. 차선을 유지하며 끝에 닿으면 반대편으로 순환합니다. `PoliceDriver`가 아니므로 충돌해도 현금은 깎이지 않고 내구도만 줍니다.
- **순찰차 시인성.** 흰 차체에 측면 스트라이프와 지붕 경광등 바를 달고 `PoliceLights`로 적청을 0.22초마다 점멸시킵니다. 근본 문제인 "뒤는 안 보인다"는 HUD에 `Patrol BEHIND 12m` 형식으로 가장 가까운 순찰차의 방향과 거리를 표시해 해결했습니다.
- **바리케이드는 교차로를 피해** 배치되므로 사거리에서는 벽이 아니라 교차 통행이 위험 요소가 됩니다. 은행 전 차단선이 줄어 주행이 빨라진 만큼 제한시간을 14/18/22초에서 **13/17/20초**로 조였습니다.

검증: 배치 로직을 포팅해 갭이 도로를 벗어나지 않는지, 건물이 교차로나 탈출 분기를 막지 않는지, 주차·통행 차량이 도로 안에 있는지 스테이지별 불변식으로 검사해 전부 통과했습니다. 주행 시뮬레이션 기준 은행 도착은 기본 세단 8.2/10.3/12.3초, 최강차 7.0/8.9/10.6초, 서툰 주행 9.7/13.3/16.0초로 제한시간까지 3~4초 여유가 남습니다. 컴파일과 Play Mode는 PC 확인이 필요합니다.

## 2026-09-11 — 바리케이드 돌파, 도시 탈출, 위협적인 경찰

문제: 세 시스템이 서로를 무너뜨리고 있었습니다. (1) 전력으로 달렸을 때 도착 시각이 약속 시각보다 7~12초 빨라서, 1스테이지 288점·2스테이지 62점·3스테이지 0점이 나왔습니다. 즉 1페이즈가 "일부러 천천히 가기"였습니다. (2) 그래서 엔진 강화가 점수를 **깎았습니다.** 풀업그레이드 쿠페는 1스테이지에서 128점으로 기본 세단(288점)의 절반 이하였습니다. (3) 경찰은 플레이어와 가속도가 같고 최고속만 낮아(24~28 vs 36~52) 간격이 벌어지기만 했습니다. 10초 뒤 84~114m까지 벌어져, "경찰에 부딪히면 돈을 잃는다"가 사실상 "혼자 장애물에 박으면 돈을 잃는다"였습니다. 현금·금고·장갑 시스템 전체가 발동하지 않는 위협 위에 얹혀 있었습니다.

변경:

- **은행 도착을 제한시간 방식으로.** 신고를 받은 경찰이 도로마다 바리케이드를 세워 둔 설정으로 바꾸고, 각 차단선에 갭을 하나만 뚫었습니다. 점수는 `clamp01((제한시간 - 도착) / (제한시간 - 기준시각))`이라 빠를수록 항상 유리합니다. 강도는 처음부터 은행에서 대기하므로 `crewExitTime`·`lateGrace`·`arrivalScoreWindow`를 `bankDeadline`·`arrivalParTime`으로 정리했습니다.
- **바리케이드 생성.** 시드 기반으로 차선 5개 중 하나에 갭을 두고, 연속한 두 줄이 같은 차선을 쓰지 않게 했습니다. 은행과 탈출 분기 주변은 비웁니다. 기존 `Roadworks`를 대체합니다.
- **승리 조건을 탈출 구역 도착으로 교체.** "65m 간격 N초 유지"(`MissionState.Escaped`, `escapeDistance`, `escapeSeconds`)를 삭제했습니다. 본선 끝 부근에서 오른쪽으로 갈라져 도시 밖으로 뻗는 탈출 도로를 만들고, 끝의 `CITY LIMITS` 구역에 반경 10m로 진입하면 성공입니다. 속도 제한이 없어 전속력 통과가 가능하고, 본선 끝은 막다른 길입니다.
- **경찰을 실제 위협으로.** 직선 최고속을 38/46/56 m/s로 올려 최강 차량 풀업그레이드(약 52 m/s)보다 약간 빠르게 하고, 가속도는 9/9.5/10으로 낮췄습니다(플레이어 14~22). 이제 직선에서는 붙고 바리케이드 재가속 구간에서 벌어집니다. `policeSpeed`의 Range 상한을 35에서 80으로 넓혔습니다.
- **경찰 AI 개선.** `PoliceDriver`가 `WorldBuilder.NextRoadblock`으로 갭 위치를 읽어 조준하고, 제동거리 안에 들어오면 감속합니다. 갭 정보가 있을 때는 기존 SphereCast 회피를 끕니다.

검증: 새 규칙을 파이썬으로 포팅해 16개 검사 전부 통과. 주행 모델 수치 적분으로 도착 시각과 추격을 확인했습니다. 은행 도착은 기본 세단 8.2/10.1/12.2초(829/878/891점), 최강차 7.0/8.6/10.5초(전부 만점), 서툰 주행 9.8/12.5/15.9초(600/611/555점)로 **강화가 점수를 올리는 방향**이 되었습니다. 추격은 깔끔하게 몰면 11~14초에 탈출 구역까지 벌어지고, 한 번 완전 정지하면 최대 간격이 40m대에 머물며 경찰이 계속 따라붙습니다. 월드 배치는 갭이 도로 밖으로 나가지 않는지, 은행·분기 입구를 막지 않는지 프로그램으로 검사했습니다. 컨테이너에 .NET SDK와 C# 컴파일러를 설치할 수 없어(egress 차단) `Tests/CareerRules.Tests`와 Unity Play Mode는 PC에서 확인이 필요합니다.

## 2026-09-11 — 은행 약속, 현금 손실, 저장형 상점

요청: 정해진 시각에 은행 도착 시 점수, 탑승 뒤 경찰 충돌 피해에 비례하는 현금 손실, 탈출 잔액 영구 저장, 차량·업그레이드 구매.

기준: 최신 `11db7ba`(testplay). 기존 조향·드리프트·속도 카메라와 에디터 저장 씬을 유지함. 현재 사용 중인 폴더와 별도 작업 폴더에서 제작.

규칙: 첫 정차 시각으로 점수를 확정, 조기 대기·재진입으로 점수 재계산 불가. 예정 시각에 강도 등장, 이후 2초 정차 탑승. +12초 기한 내 탑승 실패 시 임무 실패. 점수는 현금과 별도이며 성공 시 기록 저장.

경제: 탑승 시 현금 지급, 경찰의 실제 내구도 피해만 현금 감소에 반영. 성공 시 잔여 현금을 지갑에 입금하고 실패 시 기존 지갑 유지. 임무 ID로 중복 정산 차단. 저장 실패 시 거래를 반영하지 않고 결과 화면에 재시도 제공.

상점: 기본 세단, 고속 쿠페, 고내구 밴. 차량별 엔진·타이어·장갑·현금 보호 각 3레벨. 구매·장착·강화를 저장하고 다음 임무에 적용. 별도 Varco 차량 슬롯과 기본형 차량 외형 제공.

저장: 기존 해금·성공 횟수 이관, 지갑·차량·점수 추가. 검증·flush한 임시 파일 교체와 백업 복원, 손상/미래 버전 보호. 검사 중 Windows 메타데이터 병합 권한으로 File.Replace가 실패하는 문제를 찾아 선택적 메타데이터 오류 무시 옵션으로 수정함.

검증: 실제 경제·저장 코드의 42개 .NET 검사 통과, Unity API 참조 C# 컴파일 오류 0·경고 0. Unity 배치 실행은 Package Manager IPC에서 실패해 새 UI·물리 Play Mode는 미검증. 상세 결과는 `VALIDATION.md`에 구분.

수정 수치는 `CAREER_GAMEPLAY.md`에 기록. 은행 도착, 강도 등장, 현금 손실, 정산, 상점 거래 및 지갑·소지금·점수를 JSONL에 기록.

## 2026-09-11 — 주행 감각 개선

문제: 초기 모델은 선회 속도가 5m/s 이상에서 75°/s로 고정되어 저속에서는 둔하고 고속에서는 예민했습니다. 키보드 입력이 0과 1 사이를 즉시 오가 조향이 디지털하게 느껴졌고, Space는 접지만 낮출 뿐 강한 감속이 함께 걸려 드리프트가 성립하지 않았습니다. 공중에서는 `FixedUpdate`가 조기 반환하며 각속도를 정리하지 않아 착지 자세가 틀어질 수 있었고, R 복구는 보간이 켜진 상태로 위치를 바꿔 화면에 잔상이 남았습니다.

변경:

- 조향 입력을 초당 8단위로 스무딩해 키보드 입력에 무게를 부여.
- 선회 속도를 속도에 따라 120°/s(저속)에서 52°/s(최고속)로 보간. 정지 상태 제자리 회전은 2.5m/s 미만에서 차단.
- Space를 조향량과 속도에 따라 해석. 직진 제동은 기존대로 강하게, 조향을 넣은 제동은 감속 계수를 4.5에서 0.8까지 낮추고 접지를 2.2로 떨어뜨려 속도를 실은 드리프트가 가능. 선회력 1.4배 보너스. 접지는 초당 5로 천천히 회복되어 슬라이드가 이어짐.
- 경찰차는 `handbrakeDrift = false`로 접지를 유지. 미끄러지는 추격자는 압박이 되지 않기 때문.
- 최고 속도 도달을 마지막 20% 구간에서 점진적으로 처리해 가속이 벽에 부딪히듯 끊기지 않도록 수정. 후진 최고 속도를 상수 -10에서 `reverseTopSpeed` 필드로 분리.
- 무throttle 관성 주행에 엔진 브레이크 성격의 감속(0.16)을 추가. throttle 중에는 0.08로 유지해 최고 속도는 약 124km/h.
- 공중에서도 각속도를 0으로 유지해 착지 자세 유지. `Grounded`, `SlipAngle`, `Drifting`을 공개 속성으로 노출.
- `Recover`가 보간을 잠시 끄고 이동한 뒤 복원하도록 수정해 순간이동 잔상 제거.
- `FollowCamera`를 속도 연동으로 변경. 거리 8.5→12.5m, 높이 4.6→5.8m, FOV +14°를 속도에 따라 보간하고, 슬립 각도만큼 카메라를 슬라이드 바깥쪽으로 최대 2.6m 이동.

검증: 수치 적분 시뮬레이션으로 `SmokeTests`의 세 가지 물리 검사(2초 전진 26.8m·25.9m/s, 1.5초 제동 후 0.02m/s, 경찰 추격 전진) 통과를 확인. 0-100km/h 2.16초, 최고 124km/h, 관성 주행 3초에 124→77km/h, 드리프트 0.4초에 108→78km/h. 실제 Unity Play Mode는 여전히 미검증이며 PC에서 확인이 필요합니다.

## 2026-09-11 — 초기 프로토타입

요청: 스테이지식 3D 경찰 추격 레이싱. 주인공은 강도단 운전수이며 동료를 태워 은신처로 이동. Unity·GitHub 기반 변경 기록, Varco 3D 모델 교체 지원.

결정: PC 키보드 1인용, 설치된 Unity 6000.6.0f1, Built-in 파이프라인, 외부 필수 패키지 없는 프로토타입. 휠 시뮬레이션 대신 Rigidbody 힘·속도 기반 아케이드 조작. 경로 탐색 베이크 없이 작동하는 평탄한 도로와 장애물, 근접 회피 경찰 AI.

구현: 3개 ScriptableObject 스테이지, 브리핑, 정차 탑승, 경찰 생성·추격, 연속 거리 유지 시 탈출, 목적지 정차 성공, 체포·파손·시간 초과 실패, 다음 스테이지, 재시작, 일시 정지, 차량 복구, 해금 저장, 이벤트·차량 상태·오류 기록, Varco 프리팹 슬롯, 씬 생성 및 Windows 빌드 메뉴.

검증: 실제 Unity 어셈블리 기반 C# 컴파일 오류 0·경고 0. Unity 배치 실행은 Package Manager IPC 및 Licensing Client 연결 실패로 중단. Play Mode/빌드 미검증. 상세 구분은 `VALIDATION.md`에 기록. 씬과 에셋은 직접 YAML로 생성하고 GUID 참조를 정적 검사.

GitHub: 사용자가 새 저장소 생성을 요청. 플러그인에 생성 도구가 없어 사용자가 앱 내 브라우저에 직접 로그인한 뒤 `alphamon1114/getaway-driver-unity` 비공개 저장소를 생성함. 이후 업로드는 GitHub 플러그인으로 수행. 인증 정보는 프로젝트에 저장하지 않음.

업로드 검토: Unity 자동 생성 설정의 `ps4Passcode` 필드가 민감 정보로 분류되어 최초 업로드가 차단됨. PC 대상에 불필요한 해당 필드를 제거하고 나머지 인증 관련 설정이 비어 있거나 기본 비활성 값인지 확인한 뒤 재시도. Git 훅 비활성화 옵션 역시 검토에서 거부되어 적용하지 않고 기본 Git 설정을 유지함.
